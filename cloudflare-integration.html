Cloudflare Hosting & Database Integration

Recommended architecture

This site is now structured so the front end can be hosted as a static site on Cloudflare Pages while the data layer can be served from Cloudflare Workers + D1 or a managed database such as Cloudflare D1.

1. Create the initial database schema

  • users
  • teams
  • fields
  • leagues_tournaments
  • matches
  • umpire_preferences
  • notifications

2. Cloudflare deployment plan

  1. Deploy the static HTML/CSS/JS files to Cloudflare Pages.
  2. Create a Cloudflare Worker API for authentication, profile updates, match creation, and notifications.
  3. Store the application data in Cloudflare D1 or another Cloudflare-backed database.
  4. Use Cloudflare Turnstile or an internal auth layer for login if you want to move beyond the local demo storage.

3. Initial application manager account

The first user should be created as Shaun with the application manager role so they can manage subscriptions, users, and system-wide access.

4. Email notifications

Each assignment, acceptance, decline, or new registration should trigger an email notification through Cloudflare Workers + an email provider such as Resend or SendGrid.

5. Role-based workflow summary

  • Umpires: capture availability, receive assignments, accept or decline games, and apply to open matches.
  • Managers: create matches, select tournaments/leagues, assign preferred umpires, and record results.
  • Owners: manage organisations, licences, sport/team limits, and manager access.
  • SAHA Representatives: manage teams, fields, umpire levels, and league/tournament definitions.
  • Application Managers: manage subscriptions and have unrestricted access.
